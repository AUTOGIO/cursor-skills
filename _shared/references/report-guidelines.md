# Report Guidelines

## Output Location

Follow [output-policy.md](output-policy.md). Every report must include its **absolute path** in the header. The completion summary must repeat that path.

## Structure Principles

- Executive summary first
- Explicit scope and limitations
- Evidence-backed conclusions only
- Concise system/repository map
- Findings summary table
- Prioritized remediation plan
- Maximum **ten** quick wins
- Deferred improvements separated from urgent work
- Unresolved questions listed honestly
- Final recommendation that is actionable

## Writing Rules

- Avoid generic filler
- Do not repeat the same finding in multiple sections
- Distinguish current-state facts from recommendations
- Prefer concrete paths, commands, and IDs over vague language
- Keep remediation staged: preserve → stabilize → reliability → simplify → maintain
- Remediation plans describe *what* to do; skills in audit/diagnostic mode must not implement them unless the user explicitly authorizes implementation

## Quick Wins Criteria

Each quick win must be:

- Low risk
- Limited effort
- Measurable
- Independent of a major redesign
